**Question.** For every Stakeholder, do their Requirements reflect the priority of their Concerns? Specifically, if a Stakeholder has a High-priority Concern, do they have at least one High-priority Requirement?

```matrix
---
rowColumnLabel: "Stakeholder (concern priority) / Requirement priority"
stylesheet:
  - selector: cell [Number(value) == 0]
    style:
      background-color: mistyrose
  - selector: cell [Number(value) > 0]
    style:
      background-color: lightgreen
  - selector: cell [col === "High" && Number(value) == 0 && String(row).includes("concern High")]
    style:
      background-color: "#DC2626"
      color: white
---
PREFIX base: <https://www.modelware.io/sierra/base#>
PREFIX stakeholder: <https://www.modelware.io/sierra/stakeholder#>

SELECT ?row ?column (COALESCE(?n, 0) AS ?value)
WHERE {
  # Rows: every Stakeholder, labeled with the priority of the Concern(s) it expresses
  {
    SELECT ?s (IF(COUNT(?cp) = 0, "none",
                  GROUP_CONCAT(DISTINCT STR(?cp); SEPARATOR="/")) AS ?concernPriority)
    WHERE {
      ?s a stakeholder:Stakeholder .
      OPTIONAL { ?s stakeholder:expresses ?c . ?c base:priority ?cp }
    }
    GROUP BY ?s
  }
  BIND(CONCAT(REPLACE(STR(?s), "^.*[#/]", ""), " (concern ", ?concernPriority, ")") AS ?row)

  # Columns: every Requirement priority level in use
  { SELECT DISTINCT ?column WHERE { ?r a stakeholder:Requirement ; base:priority ?p . BIND(STR(?p) AS ?column) } }

  # Cells: Requirements stated at that priority; COALESCE turns misses into explicit 0s
  OPTIONAL {
    SELECT ?s ?column (COUNT(DISTINCT ?req) AS ?n)
    WHERE {
      ?req a stakeholder:Requirement ;
           stakeholder:isStatedBy ?s ;
           base:priority ?p .
      BIND(STR(?p) AS ?column)
    }
    GROUP BY ?s ?column
  }
  BIND(IF(?column = "High", 1, IF(?column = "Medium", 2, 3)) AS ?rank)
}
ORDER BY ?row ?rank
```

**Interpretation.** A Requirement should reflect at least the same level of urgency as the Concern behind it. A red cell highlights a Stakeholder who has a High-priority Concern but no High-priority Requirement. That could mean the Requirement was given too low a priority, or it could mean the original Concern was rated too highly.

Not every zero in the table represents a problem. For example, if a Stakeholder has only Low-priority Concerns and no High-priority Requirements, that is completely consistent.

The grid is generated by first creating every Stakeholder and priority combination before counting the data. That way, missing combinations appear as an explicit 0 instead of simply being absent from the results.

One interesting thing this analysis revealed is that Sierra does not provide a direct relationship between a Requirement and the specific Concern it addresses. Because of that, the comparison can only be made indirectly through the Stakeholder. That ended up being a useful finding about the vocabulary itself.
